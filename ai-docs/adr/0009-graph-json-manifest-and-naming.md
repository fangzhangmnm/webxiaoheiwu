# ADR-0009 graph.json 清单 schema 与节点命名规则
> created 20260909 · by Claude Fable 5.1 (claude-fable-5-1) · status: accepted（user 2026-09-09 grill）

## schema（version 1）

```json
{
  "format": "webxiaoheiwu",
  "version": 1,
  "wroteWith": "2.0.0",
  "nodes": {
    "夏音-第三次见面.txt": { "links": ["夏音.txt", "_废-第一版开场.txt"], "created": 1757400000000, "modified": 1757403600000 },
    "夏音.txt": { "links": [], "created": 1757300000000, "modified": 1757300000000 }
  }
}
```

## 决定
1. **身份 = 完整文件名 = 显示名**（`contents/` 下的 entry 名）。这是对 ORA 的一处明知偏离（ORA id 在清单、文件名派生）：graph.json 是可丢的 metadata，名字若住清单，丢清单等于丢名字。延续 ADR-0001 / ADR-0007「身份 = 路径名」。
2. **links 元素只允许名字**，且是**带扩展名的完整文件名**（user 选 A）。不允许分节行：user「`===` 是灵活语法导致的滥用，就和很多语言一样，我们的小黑屋本来就极简的」。分组靠命名前缀（`_废-…` 沉底）。
3. **占位符** = links 里出现、`contents/` 里没有的名字（Obsidian 未解析链接同款）。跳上去才生文件。零机制。
4. **边有向、零属性、零权重、零类型**。顺序 = 数组顺序（用户手排）。**反链不存**，是查询：在所有 links 里搜这个名字。
5. **撞名 = 完整文件名相等**，比较口径**大小写不敏感 + NFC**，扩展名不特殊：`夏音.txt` 与 `夏音.jpg` 是两个节点，合法共存。多个点不构成问题——身份不解析名字。扩展名只在渲染时解析（最后一个点之后），app 建的文件永远带 `.txt`；不认识的扩展名显示名字、不打开、不猜。
6. **打已有名字 = 链接不是新建**（wiki 规矩；撞名是强迫面对 pile of shame，user 同意）。不允许重名，不做 `.001`。
7. **改名** = 改 entry 名 + 重写所有引用它的 links 数组，一次整包写。
8. **created / modified 必有**（user「时间戳要」）：zip entry 时间戳钉 1980 后无处可放；`created` 事后补不回。只用于临时查询排序，**不做「最近编辑」面板**。这里没有 timelapse 那种「内耗即增重」，时间戳不长体重。
9. **`version` 太新 → 横幅 + 禁覆盖**（抄 WeebPaint `weebpaint:format` + `wrote-with`）。

## 系统对图零态度（journal 里 user 拍板，写进这里防漂移）
没有全图视图、没有全文件列表、没有孤儿面板、没有计数 / 进度 / 衰减 / 自动强弱。「有了就露馅」。检索至少两个字符、结果临时不留面板。工具唯一义务：不在用户没叫它的时候自己动。

## 否决
- stem 撞名（要定从第一个点还是最后一个点切，两种都有反例）。
- 不透明 id + `name` 属性（要自己维护唯一性；user 明确不许重名）。
- 边的强弱 / 档位 / 衰减（都是钮，都会变成形式判断）。

## 修订 2026-09-10（user 真机打回，edited by Claude Fable 5.1；格式不变，只改 UI 口径与默认）
- **显示名不带扩展名**（user「吃书：还是不显示扩展名吧」）：§1 的「身份 = 完整文件名 = 显示名」改为「身份 = 完整文件名；显示 = 去 `.txt` 的 stem」（`src/project/naming.ts` `nodeDisplayName`；别的扩展名照显）。graph.json / links 仍是带扩展名的完整文件名，§2/§5 不动。
- **新边加末尾**（user「节点应该加在末尾」）：`link()` 默认 `at:"bottom"`，取代 09-09 journal 的「默认顶部 = 最新最热」。
- **检索不限字数**（user「检索不限字数，这样可以搜全量孤儿」）：最少 1 字，取代「至少两个字符」；结果仍临时不留面板。
- **节点默认名 = 「第 N 章」按界面语言生成**（user「默认节点就叫第一章」「根据当前语言自动生成」）：不再是 `yyyymmdd-hex4.txt`。
- **节点名 UI = 纸面顶部章节名框**（v0.2.15 被 ADR-0007 撤掉的 `#titleInput` 捞回来当节点名用；user「节点名就用之前很可惜被弃置的章节名的 ui」「当前节点的改名也用这个章节名的机制」）。ADR-0007 对**工程文件名**仍有效（顶栏、点了改名）；工程内节点名不是文件名句柄那一档。

## 修订 2026-09-10 深夜（删除模型 + 名词；edited by Claude Fable 5.1）
- **删除 = 丢引用（GC 语义）**：行菜单「移出」只断当前页→它的边；它若因此**没有任何页指向**（孤儿、且有文件）→ 改名 `_废-<名>`（撞名加序号）让原名腾出来（user「删除模型就是 gc 里面的丢引用呗。node 还在，应该不需要 .trash。只有孤儿才可以彻底删，需要弹框确认。以及被删除的节点 name convention 改一下，这样删了第一章之后你可以新建第一章不会撞」）。**书里不做 .trash**（取代同夜「zip 里加 trash 机制」的念头）。
- **彻底删除只准孤儿**（`purgeOrphan`；还有人指向 → 拒绝），弹框确认；入口 = 检索结果里孤儿行的菜单。
- **名词**：用户面「节点」改叫「页」（user「一个节点叫一页……地图，插画也是一页，认知的处理单位也是一页。ui 文案先改吧，数据契约要不要吃书我们定」）。graph.json 的 `nodes` 键**不动**，等 user 定。

## 产品理念（不是机制；user 2026-09-10 口述，Claude Fable 5.1 落档）
> user：「although the user have full authority to design their graph based data structure, i think it is a clever idea to treat chapters as a linked list just like blockchain, instead of have a master table of contents node links to each chapters」「没有机制上面的东西。只是产品设计理念和 vision」

- **章节 = 链**（每一页指向下一页），而不是**一个目录页指向所有章**。书的脊柱就是这条链；目录是从第一页顺着出边走出来的派生物，不是一个特殊节点。
- 用户对自己的图有完全的设计权：链和目录页在数据上没有区别（目录页只是一个出边很多的页），app **不强制、不检查**。这条只是推荐的心智模型与默认手感：「+ 加页」从当前页末尾长出一条边——在最新一章上按 + 自然长成链，在目录页上按 + 自然长成目录。
- AI 对此的看法（同日）：同意作为默认心智模型；代价是「总览」要顺链走（或检索），插入/重排是改两三条边；分叉（一页指向两个「下一页」）在链模型下天然是草稿的分支，目录模型表达不了。将来若要「一眼看脊柱」，只该是从第一页顺出边走的派生视图，不是新节点类型。
- 链的第二个好处（user 同日）：**分叉版本可以复用前缀**——两个 divergent 版本共享前面的页，从分叉点起各走各的，像区块链分叉 / git history tree；目录页模型下这只能复制整本。
- **「page 定了」**（user 2026-09-10）：页 / page 为最终名词。
