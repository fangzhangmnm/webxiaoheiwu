# ADR-0007 文件名 = 管理用句柄，不是标题；加密稿出生名 = 日期码（藏标题）
> created 20260904 · by Claude Fable 5.1 · status: accepted（user 2026-09-04「文件名不是标题的语义，可以变，是管理用的，这个可以拍板了」→「同意，开修」）

## 决定
1. **文件名只是管理句柄**：用于列表、排序、OneDrive 里认稿；**不承载「这篇稿叫什么」**。它住顶栏（`#docNameButton`），点了走改名 sheet；编辑器里**没有标题框**（v0.2.15 的 `#titleInput` 撤掉）。
2. **有名保名，无名日期码**（ADR-0001 不变）：用户显式给名就用；没给 → `yyyymmdd-hex4.txt`。
3. **加密稿藏标题靠名字不透明**：加密稿出生名一律日期码；已有明文稿转加密 → 封完自动改成日期码（`renameDocToOpaque`，日期沿用原名 8 位前缀）；改不成（离线谱系不明 / 撞名）→ toast 响亮说「文件名仍带标题」，绝不静默。解密方向不改名。
4. 改名 sheet 文案必须说清「OneDrive 上可见（加密稿也一样）」——用户逐篇决定漏多少（想认得出就自己改成「日记三」之类）。
5. **本 ADR 零 store 改动**：身份仍是路径/名（store ADR-0011），库不解释名字；回收站 / .backup / 冲突 sheet 的名字自动跟着不透明。

## 背景
v1（`20260524-encryption.md`）威胁模型明写「微软读不到正文和标题」，加密稿存 `.enc/enc-<8hex>.bin`。v2 换代（ADR-0002）为对齐 WeebPaint 改成 `YYYYMMDD 标题.txt.zip`，标题外露，标为「待 user 复核」。2026-09-04 user 复核：「我记得最早的时候我们设计加密方案的时候名字也是加密的」→ 讨论两种模型（加密稿名字整个藏 vs 全家统一「文件名 = 管理助记符」）→ 拍板后者（前者的超集：默认什么都不漏，想认得出自己改）。

## 否决 / 不做
- **不在 .txt 里发明标题**（第一行 = 标题 / sidecar / 头部标记）：user「anti abandonware 的话我对任何 hidden convention 过敏」。标题的标准写法 = markdown `# `，归下一纪元（所见即所得，见 `20260904-0.3-knight-and-store-backlog.md`）。
- 列表里解锁后显示真标题（peek 增强）：需要 store 加 `RawFile.readPeek`（实现在库里已有、被 isZip 门挡着）+ 每篇一次 PBKDF2×250k（Quest 上 0.3–1 s/篇）。**没做**，等所见即所得纪元有了 `# ` 标题再议。
- 日期码带不带日期：保留日期（可排序、家族惯例；OneDrive 元数据本来就漏修改时间）。
- 藏名做进 store（库层「文件名加密」）：撞 store ADR-0012「名字明文只藏字节」，且要改遍回收站/备份/冲突每个面——app 层起不透明名一处解决。

## 后果
- 明文新稿默认也是日期码名（以前标题框有字就用标题当名）：想要可读名去顶栏改。
- `RENAME_DEBOUNCE_MS` 退役（改名不再随打字防抖，是一次显式动作）。
- `parseDocName().title` 字段名保留，语义 = 显示名（文件名 stem），不是稿的标题。
- 7-Zip 手工恢复：`meta.bin` 里的名就是日期码，正文自己认。
