# ADR-0005 每篇可有自己的密码；保存永远用打开时那把钥匙；换钥匙只能是显式动作
> created 20260903 · by Claude Fable 5.1 · status: accepted（user 2026-09-03「anti abandonware ritual 是每个文件可以有单独的密码的…这里 ux 好好设计一下」→ 提案 → 「同意，做」）

## 决定
1. **承认现实**：7z 容器各自封，所以每篇天然可以有自己的密码。app 持一张**内存表** `name → 密码`（`src/crypto-state.ts`，锁定即忘，永不落盘）；store 的 `crypt.getPassword(name)`（库本来就带 name）= 这篇自己的 ?? 当前密码。
2. **保存永远用这篇打开时那把**，绝不悄悄换钥匙（7-Zip 用户要能靠记忆打开）。
3. **「当前密码」（账号级，有 verifier）只有两个用途**：新稿默认钥匙；打开旧稿第一把试的钥匙。试不开 → `readDoc` 返 `other-password` → 「这篇稿的密码」循环（store `verifyPassword` 便宜验，错了不碰文件）→ 记进表。
4. **换钥匙 = 显式动作**：横幅「这篇用的不是当前密码 [换成当前密码]」（解开→用当前重封）；设置页「更改加密密码」= 迁移动作（验旧 → 设新 → 选「同时换成新密码」逐篇解旧封新 / 「保留各自旧密码」），碰不到的仍旧、打开时单独问；「忘记密码，重置」只清 verifier，明说旧稿不跟着变。

## 后果
- 改名（tryMove）表项跟随；回收站恢复带后缀的名会再问一次（可接受）。
- 抽屉锁图标不区分「当前/别的密码」（打开前不知道）。
- WeebPaint 同一接口（`getPassword(name)`）可直接收货这套 UX，本 ADR 未动库。
