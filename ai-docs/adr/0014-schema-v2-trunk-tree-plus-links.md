# ADR-0014 schema v2：主干树 + link（户口本 + 汤）；链表结构、占位符、link 属性三者废止
> created 20260910 · by Claude Fable 5.1 (claude-fable-5-1) · status: accepted（user 2026-09-10 深夜 grill 逐条拍板；出处 = 本日「wxhw 2.0 data archaeology」session；引文已 sanitize，只留工程语境）

## 背景
- 迁移轮用 AI 机翻做了一本 41 页的链表狗粮书，user 一上手就证伪链表：「ai狗粮证明了链表模型不是个wise choise。因为没法章节速览」。根因不是图模型，是**把结构编码成边的约定**（「第一条出边 = 下一章」）——而 09-10 已拍「新边加末尾」，在 app 里先链一条笔记再加下一章，下一章就是第二条边，静默错。
- user 同日定性：「zip 是 workbench 不是 museum！档案不应该我们做」「link 是房间的边，tree 是整理」「我们数据结构不定语义。用户就只有一个树和 link」「树重新变成清单 → 看到的是 sibling 和一个 ..」「未物化的 placeholder 这个机制扔掉，那个是 ai 拍板的」「上一章下一章就是对主树做 dfs」「edge 应该叫 link property 而不是同义词汤」。
- 可以完全吃书：库里只有迁移轮的四本书，legacy 不留分支代码。

## 决定
1. **两层数据，各管一件事。** tree = 整理（一页至多一个父亲、兄弟有序、**成员资格可选**——散页合法）；links = 指向（多对多，房间的边、wiki 关系、章节提到谁）。一句话语义：**兄弟 = 顺序，孩子 = 归属，link = 指向。** 一页可以同时活在两层里。
2. **graph.json v2**（version 直接 2；不是 v2 的一律拒开，`not-project` / `too-new` 两档，**零 legacy 分支**）：
   ```json
   { "format": "webxiaoheiwu", "version": 2, "wroteWith": "…", "readOnly": true,
     "tree": [ "扉页.txt", { "name": "第一幕.txt", "children": ["第一幕 第一话：新学期.txt"] } ],
     "pages": { "<完整文件名>": { "links": ["…"], "created": 0, "modified": 0 } } }
   ```
   `tree` 节点 = 名字字符串，或 `{ name, children }`。**树里没有 folder 类型、没有节点类型、没有 compile 标记**：组 = 有孩子的页；app 不知道哪一支是正文、哪一支是设定，那只是用户起的名字。
3. **不变量**：一个名字在 tree 中至多出现一次（重复 → `corrupt`）；tree 与 links 里的每个名字必有 `pages/` 文件（读到悬空名字 → 丢掉并记 warning，不拒开；写出绝不产生）。宽容读、严格写。
4. **占位符废止**（撤 ADR-0009 §3 及 `isStub` / `edge.stub` / 「点它就生出来」/ session「占位生文件」动词）。写作上的占位 = 一两句话的空页。名字框：打已有名 = 链接（ADR-0009 §6 不变）；打新名 = **当场建空文件**并接上，没有「名字先挂着」的中间态。
5. **link 属性废止**（撤 2.1.0 的 `edges` / `dim`）。灰不是属性：**在树里 = 前景，不在树里 = 背景**，算出来不存。以后若真需要按边挂属性，术语定为 **link property**（键 = links 里的目标名），现在不用。
6. **导航与导出**：上一页 / 下一页 = 对整棵树**前序 DFS**（纯导航，会经过设定页和图片页，不是阅读器）；导出 = 对**选中节点**的子树 DFS 拼接（在正文组上导出就是小说，在设定组上导出就是设定集）；腰封 / 封面 = 从某页「设为…」抄进 `Thumbnails/thumbnail.png`（+ iTXt Description，ADR-0012），手势不进 schema。
7. **UI 反清单化**：侧栏只显示当前页的邻域——`..`（父）、兄弟、孩子、links；**不铺整棵树**，默认只展开到当前页的祖先链。ADR-0009「系统对图零态度」（无全图、无孤儿面板、无计数）保留。
8. **树上的移动与删除模型**（2026-09-10 深夜改写；出处 = user 2026-09-10 深夜（迁移 session 转述）「不同意引用计数，那又是 cleverness. 删除是一个不同的语义。不过确实在树情况下面没有了去边」）：
   - 移动：上移 / 下移 / 升级（出到父亲那一层）/ 降级（进到上一个兄弟下面）/ 归档（把散页放到当前页之后或之下，树里的页 = 搬家、子树跟着）/ **归入主干**（散页自己进树末尾；树空时 = 第一节点，是空树唯一的入口——v2.1.6，出处 = user 2026-09-10「为什么对于txt转的书我还是只能加链接没法加孩子和兄弟」，因 v2.1.5 之前升的 txt 书 tree 为空；edited by Claude Fable 5.1 2026-09-10）。全部是对一个数组的编辑，links 不动。菜单先行，拖拽等 iPad / Quest 手感再议。
   - **删除是三个显式动词，各归一层，没有引用计数、没有「孤儿」概念**（一页没人指就是没人指，app 不替它做任何事；「非删除的变成孤儿不应自动改名」现在无例外）：
     ① **断开链接**（unlink）= 只删这一条边，永不改名、永不看对方还剩几个引用；
     ② **移出树**（detach）= x 连同子树离开树，**子树边降级成 links**（每层孩子按原顺序追加到父亲的 links 末尾，递归到每一层），结构不丢，不改名；toast「已移出树，N 页改为链接」；
     ③ **废弃**（discard，用户面 = 删除）= 改名 `_废-x`（撞名走 hex4）；在树里则连同子树出树、**子节各自也改名 `_废-`**（删容器 = 删内容，文件管理器语义）；sheet 写明「废弃「x」及其 N 个子节」；不删字节；指向它们的 links 随改名重写；散页上的废弃 = 只改名。实现时子树边同样降级成 links（= 先移出树再改名，结构可循）；
     ④ **彻底删除**（purge）= 只对 `_废-` 前缀页（任一界面语言的前缀都认）；删文件；所有指向它的 links 条目移除（v2 不许悬空）；sheet 写明「N 页链接到它，链接会被移除」。
   - 行菜单：树行 = 上移 / 下移 / 升级 / 降级 / 移出树 / 废弃 / 导出这一支；链接行 = 上移 / 下移 / 归档到这页之后·之下（目标是散页时）/ 断开链接 / 废弃；入边行 = 断开；检索里的 `_废-` 页 = 彻底删除；readOnly 全灰。
   - **图片进门的落点**（user 2026-09-10「加图片没说清楚是兄弟还是孩子」）：名字框里的「从图片…」= 先选位置（兄弟 = 当前页之后 / 子节 = 当前页孩子末尾）再选来源，多选依次排在同一位置之后保持文件顺序；拖放 / 粘贴没有位置选择 → 在树里的页上 = 当前页的子节末尾，散页上 = 从当前页链出（默认是迁移 session 定的、user 未反对）。「设为封面」不变。
9. **世界观 = hub 页 + links**（user「对就是 hub 页」）：一页「世界观」出边指各 wiki 页，可套；关系网从章节 → 人物、人物 → 人物的 links 里长出来，反链是查询。不做第二本户口本（shelf）；触发条件 = hub 页手工维护到烦，加键便宜、删键吃书。
10. **root 页 hack 退役**：书本身就是根，迁移轮为链表造的三个 root 页删除；四本迁移书重生成为 v2 夹具。
11. **命名 grill 定案**：身份 = 完整文件名（NFC + 大小写不敏感、书内唯一，ADR-0009 §1/§5 不动）；章名与 wiki 名同一命名空间；**顺序住树里，章名不再需要「第 N 章」**；无别名机制（重定向页也是页）；改名 = 改 entry 名 + 重写 links 与 tree；字符限制 = 文件系统的（`/ \ : * ? " < > |` 禁），长度 255 字节。

## 否决
链表作结构 / **引用计数式 GC**（丢引用成孤儿即改名——「那又是 cleverness」；连带「孤儿」概念一起退场）/ 「第一条边」编译目录 / 来路（back 栈）当父亲 / 每页 `parent` 指针（兄弟顺序还得另存索引）/ 树编码进 link property（`kind: child`，树性变成跨页执法的不变量，顶层顺序无处放）/ 文件名编号（序号焦虑 + 插一章全重编）/ 节点或边上的 dim / 显式 `next` 标记 / 第二本户口本 shelf（暂缓）/ 不透明 id + name（ADR-0009 已否，理由不变）。

## 后果
- ADR-0009：§2 links 纯名字保留；§3 撤销；§4「顺序 = 数组顺序」现在只指 links 内的引用顺序，结构顺序住 tree；「产品理念：章节 = 链」节**作废**（狗粮证伪）；2.1.0 `edges` 修订撤销。
- ADR-0008：zip 目录清单不变（graph.json 内容换 v2）；2.1.0 的 `Thumbnails/thumbnail.png` 与图片页照旧（ADR-0012/0013，隔壁「wxhw v2 image thumbnail specs」session 落档）。ADR-0010 不变。
- 实现 handoff = `ai-docs/20260910-v2-tree-schema-handoff.md`；迁移夹具 = `tmp/migration/`（不进 git，`build_books.py` 可重生成）。
- app 版本号归 user / 实现 session 定（家规：AI 不提 major）。
- **落地 2026-09-10 深夜 v2.1.1**（树 session，Claude Fable 5.1；状态见 `ai-docs/20260910-v2-ui-handoff.md` §4 末「v2.1.1」节）。实现时定的两条读法：§8「升级」= x 出到父亲那一层、插到父亲之后（x 已是顶层 → no-op）；「+ 兄弟 / + 子节」打已在树里的名 = 位置不动只跳过去，打散页名 = 归档到这里。
- **v2.1.7（2026-09-10，Claude Fable 5.1）**：§8 的「归档」动词升级成通用「挪到…」——一个 pick sheet（搜索 + 自绘列表，`sheets.ts openPickSheet`）选主干里的锚点 → 放到它之下 / 之后 / 书的末尾（= v2.1.6「归入主干」并入）；三处入口（散页侧栏首行 / 顶栏「+」菜单 / 树行 ⋯ 菜单）；自己 / 自己的子树 / `_废-` 不给选；子树跟着走；命中行只显示名字（user「key 是唯一的」）。原语不变（`attachUnder / attachAfter / attachAtEnd`），只是 UI 从「拉它到当前页旁」补上了「把这页送过去」的方向（user「点之后弹一个对话框，搜索，下拉，选中，就 reparent 了」「reparent 是之下，但是同意你说的第二个选项」）。「链接行 → 归档到这页之后 / 之下」照旧。
- **v2.1.28（2026-09-30，Claude Fable 5.1）：「孤儿」一词有限回归——只是一个入口，不是概念**。user 2026-09-30「wxhw 我需要一个检查废弃的页彻底删除的工具」「不是一键全删除，而是一个系统的列举所有孤儿的入口」。侧栏导航底部「孤儿页 · n」（有才露）→ pick sheet 列出 `_废-` 页 + 没有入链且不在主干的散页，每页可打开 / 挪到… / 废弃 / 彻底删除（只对 `_废-`，删前确认）。**不变的**：没有引用计数、app 不替任何页做任何事、没有「全部删除」；散页仍然合法——列表只是把它们摆出来让人看一眼。§7「不做孤儿面板」中「面板」（常驻区块）仍不做，这是按需打开的清单。

- **修订 2026-09-30（页属性 `hidden`；edited by Claude Fable 5.1）**：导出纪元第一个契约改动。user 原话「如果缺省发布的话，我建议还是和unity一样，parent hidden -> all child hidden，免得有奇怪的孤儿。所以就用hidden？」「之前的卫生是我们不帮user发明语义，只用最generic 机械的，所以就hidden?而不是用旗子？」——四值旗子（草稿 / 笔记 / 旧稿）作废，只加一个布尔。`pages[名].hidden: true`（只写 true，缺 = 出门）= 这页**自己的**旗子（Unity `activeSelf`）；**有效值 = 自己 ∨ 树上任一祖先**（`activeInHierarchy`），**只沿树（归属）传播、不沿 links（指向）**——这就是 2.1.0 强弱边念头的落点。出门（「导出这一支」txt / 长图 / 将来的 PDF / 字数统计）看有效值：hidden 的节点连同整支跳过；workbench（上一页 / 下一页、侧栏、检索、参考窗）什么都看得见：自己藏的行画眼睛 + 灰，被祖先藏的只灰（Unity Hierarchy 同款）；纸上章节名旁露一只眼睛（自己藏的点了取消；被祖先藏的点了说是谁）。散页只看自己。新建子节不抄旗（祖先传播已经盖住）；移出树（子树降级成 links）= 孩子脱离祖先的遮蔽，自己的旗子不动。封面来源页（ADR-0012 `cover`）**不受 hidden 影响**（封面是显式提拔过的书级元数据，不是阅读顺序）。§2 的「树里没有节点类型、没有 compile 标记」不变——hidden 是页的属性，住 pages 表，树仍只管归属与顺序。version 仍 2。落地 v2.3.2：`graph.ts` isHidden / setHidden / hiddenAncestor / isHiddenInTree / visibleOrder / visibleSubtreeOrder；`exportSubtree` 改走 visibleSubtreeOrder；session `exportOrder`；侧栏 / 顶栏「+」菜单「隐藏（不出门）/ 取消隐藏」；导出 sheet 头一行「整本出门的：N 字 M 词 · P 页（隐藏的不算）」= user「统计字数只看 publish 的」的落点。
- **修订 2026-10-01（点名导出不看自己的 hidden；edited by Claude Fable 5.1）**：user 原话「对了，导出当前支和本页的时候忽视本页的visibility，只看子叶的」。hidden 管的是「跟着整本 / 跟着上级出门时带不带它」；人点名导出这一页 / 这一支时，被点名的那一页一定出门（它自己的旗子、祖先的旗子都不看），它**底下**的页照旧——自己标了 hidden 的连同整支剪掉。整本导出与字数统计不变（看有效值）。实现 = `graph.ts visibleSubtreeOrder`（root 恒在 + `visibleOrder(children)`）；09-30 首版的「root 被藏 → 空」与文案「这一页是隐藏的，不出门」退役。
