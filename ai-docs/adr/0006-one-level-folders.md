# ADR-0006 多文件夹：身份 = `[夹/]YYYYMMDD 标题.txt`，只一层，根 = 默认夹
> created 20260903 · by Claude Fable 5.1 · status: accepted（user 2026-09-03「我说了毕业对齐，就是需要支持多文件夹」→ 形状提案 → 「多文件夹同意，现在就要」）。修订 ADR-0001 的「appfolder 根平铺」。

## 决定
- 稿的身份仍是路径/名（§A 不变），只是允许一层前缀：`小说甲/20260903 第一章.txt`。根目录 = 默认夹，老稿零迁移。
- 列举 = `watchFolder(当前夹)` 一夹一订阅（快照自带 immediate 子夹）；抽屉顶部面包屑「全部稿件 › 夹」；打开抽屉时跳到当前稿所在夹。
- 动作：新建文件夹（只在根；`files.newFolder`，离线可建回线补）；稿「移到…」（`tryMove` 到目标夹，撞名追加后缀；当前稿走 `editor.moveTo`，改名/密码表/只读名单跟随）；删**空**夹（库内证实为空，离线无法确认 → 拒绝并响亮报错）。
- 新稿落在抽屉正看着的夹（`newDoc({dir})`）；回收当前稿后的空新稿留在原夹。
- 回收站 / 备份箱 / 冲突 / 加密：全是库级，按路径工作，不动。

## 后果
- 面包屑只一层：夹里不再显示「新建文件夹」。想要子夹时再议（不预留）。
- 云端回收站的 cloud-only 行只剩 basename（库注释：folder context 在云端 trash 已丢）→ 恢复落根，可再移。
- 跨设备 lastActive / 本机 last-open / 只读名单存的都是全路径，天然兼容。
- 出厂重置的「未同步稿」门改用库的 `files.dirty.count()`（全库标量），不再只看当前夹。
