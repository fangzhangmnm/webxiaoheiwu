# 提案：一张纸——纸面整张滚动，正文框不再内部滚动
> created 2026-09-29 by Claude Fable 5.1 · as-of v2.1.23（+ 未发版的首键预热 / 候选条两条提交）
> 状态：**提案，未动代码，等 user 点头。** 它同时回答三件事：横线抖动、纵向空间、将来的 markdown / LaTeX。

## 0. 一句话

现在的纸是「顶栏 + 一个自己会滚的正文框 + 钉在下面的字数条」。改成「一张会滚的纸」：顶栏一条常驻，纸从标题到页脚是一整张，正文框有多少字就多高、自己不滚，滚的是纸。
写字线画在纸上，字和线是同一层，永远不会相对抖。将来 markdown / LaTeX 只是往这张纸上换一种东西画，纸本身不用再改。

## 1. 起因（user 2026-09-29 原话）

> 优化一下纵向的空间利用率 最好就是除了键盘就是字 最下面的字数统计可以和subpages一样是印在页面的脚上吗，然后标题和导航也是跟着纸走，也许你需要好好理一下css和dom
> 反正zen mode的意思就是你写的时候就是键盘和字啊，各种功能按钮需要的时候找得到就行，所以一张纸，顶端是标题和导航，底端是导航和页脚，这样文字可以多吃一点空间
> 然后最顶端的状态栏倒是需要常驻，不过也可以弄得省一点纵向空间
> 顺便一件小事，纸的横线滑动的时候还是和文字有相对抖动。能不能跳出来换一个更优秀的思路
> 所以就是这张纸怎么渲染。以后可能还会支持github markdown, including latex呢

## 2. 现状怎么画的（v2.1.23）

| 层 | 现状 |
|---|---|
| 顶栏 `.top-bar` | 固定在最上，约 48px：书库钮、文件名、加密 / 只读 / 保存钮、状态字、中 / 英、加页、菜单 |
| 纸 `.page` | 一块占满剩余高度的容器：回上一级链接、章节名行（上一页 / 章节名 / 下一页）、`.page-body`、字数条 `.page-foot` |
| `.page-body` | 正文 `<textarea>` **自己内部滚动**（`overflow-y: auto`）；有子节的页走「嵌入态」：正文框按内容高度伸缩、子节目录紧跟其后、超过一屏才退回内部滚动 |
| 写字线 | `.body` 的 `background-image: repeating-linear-gradient` + **`background-attachment: local`**，让背景跟着正文框内部滚动 |
| 字数条 | 纸底钉着的一条，占一行高 |
| 话筒 / 键盘钮 | 纸面右下、左下的浮钮 |

## 3. 抖动的根因

线跟着正文框内部滚动靠的是 `background-attachment: local`。**下面是我对根因的判断**（依据 WebKit 的实现方式；无头 Chromium 量不出这种抖动，真机验证归 user）：在 WebKit（iOS / iPad）上，滚动容器的内容是合成层滚动（GPU、逐帧），而 `background-attachment: local` 的背景是主线程重画后再贴上去的——动量滚动时两者差一帧，字先走、线后到，看起来就是线在抖。
Chromium 桌面把这种背景也提升成合成层，所以无头审计量不出来；user 在真机上看到的就是这一帧差。
这不是参数能调好的：只要「线画在一个会滚的框的背景上」，WebKit 就会这样。**根治 = 那个框不滚。**

## 4. 目标形状

```
┌──────────────────────────────┐  顶栏：常驻，一行，36px（书库 · 文件名 · 状态 · 中/英 · 菜单）
│ ┌──────────────────────────┐ │
│ │ .. 父页名                 │ │  ← 纸从这里开始，整张纸在 main 里滚
│ │ ‹  章节名              ›  │ │
│ │ 正文……                    │ │  正文框有多少字就多高（不内部滚动）
│ │ 正文……                    │ │
│ │                          │ │
│ │ 子节一            09-28  │ │  子节目录（现有）
│ │ 子节二            09-27  │ │
│ │ ‹ 上一页        下一页 ›  │ │  页脚：导航
│ │                 240 字   │ │  页脚：字数，印在纸上（和子节目录同一种排法）
│ └──────────────────────────┘ │
│  （键盘露着时这里让出 --dock-h）│
└──────────────────────────────┘
```

- **滚动的是纸**（`main` / `.page` 是唯一的滚动容器），正文框 `height = 内容高度`。已经有的孪生框 `paper.contentHeight()` 就是量这个的；能用 `field-sizing: content` 的浏览器（Chromium 123+）交给浏览器，其余走孪生框。
- **写字线画在纸上**：`.page-body` 一张 `repeating-linear-gradient`，不用 `background-attachment`。正文框、子节目录、页脚全透明，字坐在纸的线上。字和线在同一层，滚动是整层一起动。
- **顶端 / 底端**：章节名行和回上一级留在纸顶（跟着纸滚走）；页脚 = 上一页 / 下一页 + 字数，印在纸的最后几行上，和子节目录同一套整行几何。
- **顶栏瘦身**：48 → 36px；只留书库、文件名、状态一字、中 / 英、菜单；加密 / 只读 / 保存三个钮收进菜单（现在它们也只在特定状态露）。
- **浮钮**：话筒和键盘钮钉在视口（不随纸滚）；`--dock-h` 照旧让位。
- **zen**：键盘露着的时候，屏幕上 = 36px 顶栏 + 字 + 键盘。

## 5. 光标跟随（这个模型唯一要小心的地方）

正文框不滚了，「打字打到屏幕底下」靠什么把光标滚进视野？浏览器在文本框里插入字时会把光标滚进**最近的可滚祖先**（Chromium / WebKit 都是）。
但 iOS 上还有软键盘遮挡的问题——我们的软键盘是自己画的（不是系统键盘），纸的底部 padding = `--dock-h`，所以「滚进视野」就是滚进纸的可见部分，不会被键盘盖住。
兜底：`input` 之后用孪生框量光标所在行的 y，不在可见区就 `scrollIntoView`（一行代码，只在浏览器没做的时候起作用）。真机验证归 user。

## 6. 为将来的 markdown / LaTeX 留的路

纸是滚动容器、内容是纸上的一层——这条定了之后：
- 「渲染视图」= 纸上把正文框换成一块渲染出来的 HTML（或渲染层盖在正文框上），线还是纸的线，滚还是纸在滚。
- 渲染层的行高只要是 `--editor-lh` 的整数倍就仍然坐在线上；公式、表格这种不按行的块可以自己决定占几行（`aspect` 取整），线在它底下照画。
- 反过来，如果正文框还在内部滚动，渲染层就得也做成一个同步滚动的框——那正是现在抖动的来源。

## 7. 要改的东西

| 文件 | 改什么 |
|---|---|
| `index.html` | `.page` 里：页脚从字数条变成「导航 + 字数」两行；顶栏去三个钮 |

## 8. 风险

| 风险 | 怎么办 |
|---|---|
| iOS 光标跟随 | §5 的兜底；真机验证 |
| 特别长的稿（几万行）正文框全高 | textarea 全高对浏览器不是问题（一个大 DOM 节点）；字数统计已是增量的 |
| 书重载时恢复的滚动位置 | `project/mode.ts` 重载（冲突后换成云端版等）前记正文框的 scrollTop，改成记纸的 scrollTop；只在内存，格式无关 |
| 锁屏 / 空闲遮罩、toast、锁卡 | 都是 fixed 定位，不受影响 |
| 参考窗会话正在动 `index.html` / `styles.css` | 已互相通气：它的东西是独立块；我只动 `.page` 和 `.top-bar` 内部 |

1. 这个模型做不做。

3. 顶栏留什么：我建议书库、文件名、状态一字、中 / 英、菜单；加密 / 只读 / 保存收进菜单。
