> 和小窗（`20261024-mini-window-proposal.md`）是**两个独立的解法**：小窗是 PC 上浮在别的窗口上面的置顶窗；打字机模式是同一页里的一种版面，所有设备都能用。user：「你说的compact是小窗，打字机是另外一种解决方法」。

## 1. 要解决什么

在大屏上，前文铺满整个屏幕，抢注意力。写第一稿时只想往末尾追加，视野里只要最后几行（user 把它比作 `file.open -a`）。打字机模式把纸的上沿压到屏幕很下面：纸只露出底下四行，正在写的那一行钉在最下面，每写一行纸往上送一行，旧字从上沿出去。

## 2. 已定（user 10-24 拍板）

| 项 | 定了什么 |
|---|---|
| 看得见几行 | 四行：刚写过的三行 + 正在写的一行（光标在最下面那行） |
| 改什么 | 只挪纸的上沿。顶栏那一排、章节名、页脚、键盘、悬浮钮，原来占多大还占多大 |
| 进入 | 跳到最后一行，光标放在末尾 |
| 退出 | 纸的上沿还原，光标留在原处 |
| 开关 | 顶栏上一个随时能按的钮，一按就切 |
| 前文 | 没删也没变暗，往上滚就能读，只是不在那四行里。不拦人回头 |
| 不做 | 「下一站」那一行（参考窗管这件事）；前文变暗 |

**和仓规的关系**：CLAUDE.md「人类钉死的行为」写着「打开落在开头」。打字机模式里「进入时跳最后一行」是 user 10-24 定的例外，只限这个模式；平时照旧。

## 4. 实现要点（给做的人）

- **一个数**：WXHW 的顶栏 `.top-bar` 是固定在屏幕顶上的不透明带子，高 = `--sheet-top`，纸从它底下滚过（`styles.css` 文件头「一张纸模型」）。打字机模式把 `--sheet-top` 调成「屏幕高 − `--sheet-bottom` − 4 行」，带子就一直伸到纸条上沿，旧字滚上去被背景盖住。光标跟随（`scroll-padding`）、纸的最小高度（`--sheet-h`）都从它推出来，自己跟着变。
  - 行高 `--editor-lh` 写在 `.page` 上（`paper.ts` 算的整数像素），`:root` 读不到，所以这个数要由 JS 算好再写回去。
- **用到 `--sheet-top` 的其他几处要照旧**（建议另起一个「顶栏按钮那一排的高」的变量给它们用）：
  - 顶栏按钮：现在在带子里上下居中，带子变高后会飘到屏幕中间，要钉回顶上。
  - 锁屏卡 `.lock-card`、密钥横幅 `.key-banner`：照原来的位置。
  - 参考窗的上限：`app.ts` 的 `topFloor` 现在取顶栏的底边，打字机模式下要改取按钮那一排的底边，否则参考窗会被挤进纸条，进不了上面那块空地。
- **图片页不进这个模式**：图片页的纸固定一屏高（`body[data-page-kind="image"] .page`），没有字可以往下写。
- **悬浮的话筒 / 语音退格钮**：位置不变，要核一下它们不压那四行（ui-audit 加一条）。
- **大半页滚动余量**：`--sheet-overscroll` = 可见纸高 × 0.6，会跟着变成两行多，不影响「正在写的那行在最下面」。
- **要跑的审计**：ruled-audit（新上沿下线和字照样对齐）、kb-audit（iPad / Quest 软键盘露着时纸条坐在键盘上面）、ui-audit（钮、上面几处特殊情况、四行可见、光标在最下行、退出后光标不动）。
- **图标**：共享图标库里没有打字机（10-24 查过，最近的是 `keyboard`、`text`，语义都不对）。做的时候在图标库 `PENDING` 画一个，或者先烤 stopgap 再登记图标库 `TODO.md`。
