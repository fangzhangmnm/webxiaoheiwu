## 2. 我对想法的复述（AI 的话，供 user 顶）

- **问题**：pile of shame = 舍不得扔、又一直占认知资源的旧稿 / 旧版本。现有两个极端都不对：全持久化（每个旧版本的错都留在工作区里，是毒）和白板式全重置（干净，但大纲、设定这类真需要留的也没了）。
- **想法**：文本存储的基本结构是图，不是树也不是文件夹。节点 = 文本块；边有强弱。**工作集 = 强连通的那一团**；舍不得扔的东西自成一个强连通分量，只用一条弱边挂在工作集上。弱边把污染限制在一条边的范围内，而这条弱边本身就是「值得 archive」的标记。
- **和 WXHW 的接口**：WXHW 现有本体是文档 + 文件名当管理句柄（ADR-0007）。这个想法如果落进来，动的是文档之间的关系层，不是单文档内部。是否值得、怎么和加密路径相处，都没讨论。
- **user 的两条硬约束（原话可查）**：只愿意用 txt，不要 tree-based visual novel 工具那种形式；一有 human-facing 文体要求就会写成八股，所以工具不能在写的时候提形式要求。
